# Lattice 产品意图

## 一句话

Lattice 是一个**离线优先、多语言、以源码为中心的阅读平台**：把语言实现与标准库整理成可安装的源码包，让学习者用统一的方式查找、导航、阅读和记录。

它不是用户仓库分析器，也不是代码编辑器或 IDE。

## 要解决的问题

学习 CPython、OpenJDK、TypeScript、Rust、GCC/Clang 等实现时，真正困难的不是把文件打开，而是：

1. **入口难找**：一个语言概念究竟在哪个实现、哪个目录、哪个符号里？
2. **结构难懂**：调用链、数据结构和模块关系分散在大量文件中。
3. **查询不统一**：不同语言有不同的命名、导航与搜索习惯，学习成本反复出现。
4. **资料与源码割裂**：外部笔记或指南无法与同一份源码版本的位置稳定绑定。
5. **环境不稳定**：资料、链接和在线服务会变化；深度学习需要可重复、可离线保存的内容。

## 核心用户与场景

目标用户是希望理解语言内部机制的开发者、学生和进阶学习者。

典型任务：

- 从“Python list 为什么 append 很快”搜索并进入 `list_append` 与 `list_resize`，沿着符号关系继续阅读。
- 搜索“垃圾回收”“borrow checker”“type inference”等概念，找到对应学习内容和真实源码入口。
- 在不同语言源码包中使用一致的符号搜索、引用跳转、大纲、调用链和版本对比操作。
- 在源码旁记录自己的理解、书签和疑问，之后离线继续学习。

## 首批内容：语言实现与标准库

内容单位统一为 **Source Pack（源码包）**，而不是“用户仓库”。候选包括：

| 学习语言 | 源码包示例 | 主要学习内容 |
| --- | --- | --- |
| Python | CPython | 解释器、对象模型、内置类型、字节码、C API、标准库 |
| Rust | rustc / Rust 标准库 | 编译流程、类型与借用检查、核心集合与运行时设施 |
| Java | OpenJDK | JVM、类加载、字节码、并发与核心类库 |
| TypeScript | TypeScript | 编译器、检查器、类型推导、转换与语言服务基础 |
| C / C++ | GCC、Clang、libstdc++、libc++ | 编译管线、诊断、优化、标准库实现 |

C/C++ 没有唯一官方实现，因此必须明确“学习的是哪个实现、哪个版本”，不能把一个实现的行为误写成语言标准本身。

经典开源项目以后可以复用 Source Pack 协议加入，但不进入首批产品承诺。

## 核心体验

### 1. 本地源码书库

- 按语言与实现浏览和选择源码包。
- 源码包保持只读，安装后即可断网阅读、搜索和跳转。
- 多个实现可以并存，切换时不重建界面。

### 2. 源码为中心的阅读

- 平台不内建课程或固定学习顺序，阅读器直接服务于源码浏览、符号定位和关系理解。
- 文件树、标签页、符号大纲、定义/引用跳转和搜索构成主工作流。
- 后续允许导入外部 Markdown 指南；指南只是可选旁注层，可绑定到源码位置，但不改变源码包内容。
- 用户可以使用自己的资料、课程或笔记组织阅读顺序。

### 3. 跨语言统一查询

- 统一搜索文件、符号、路径与笔记。
- 统一呈现定义、引用、调用关系、继承/实现关系和未解析结果。
- 语言差异由适配器处理，不让每种语言形成一套独立 UI。

### 4. 理解资产沉淀

- 书签、笔记和阅读记录保存在本地。
- 笔记关联到源码包版本与符号身份，而不是只关联易变化的行号。
- 升级源码包后，能识别原笔记对应的位置是否仍存在或发生变化。

### 5. 离线是默认工作方式

- 应用资源、源码、索引和字体均不依赖 CDN。
- 下载/导入源码包是显式内容操作；阅读期间不访问网络。
- 在线翻译或远程 AI 不是核心依赖。

## 产品边界

首版明确不做：

- 用户私有仓库的通用索引与管理。
- 源码编辑、调试、构建任务或完整 IDE 能力。
- 内建课程平台或由官方维护的固定学习路径。
- 没有版本与来源说明的“资料大杂烩”。
- 把大语言模型生成内容当作权威源码解释。
- 假装不同语言具有完全相同的语义关系；无法解析时明确降级。

## 最关键的设计判断

过去方案以“工作区变化与索引代次”为中心，因为目标是跟踪用户仓库。

新方案以**不可变源码包版本与符号定位关系**为中心：

> Source Pack 定义真实源码版本，Symbol 定义源码中的稳定定位，Note 保存学习者自己的理解；外部 Markdown 指南是可选旁注层，查询索引只是可重建的加速投影。

这意味着首版不需要把文件监听、增量保存和仓库代次提交放在产品中心。源码包更新等价于安装一个新的不可变版本，旧版本及其笔记仍然可追溯。
